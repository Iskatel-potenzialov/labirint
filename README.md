# Vision-only Domino Escape — Jetson Nano + Arduino

Робот-тележка на базе **NVIDIA Jetson Nano** и **Arduino Nano**, которая находит и проезжает через единственный проход в кольце фишек-домино, используя **только камеру и компьютерное зрение**. Без ультразвука, лидаров и других дальномеров: всё, что есть у робота — это изображение с CSI-камеры, нейросеть YOLOv5s, простая геометрия и логика состояний.

## Идея проекта

По окружности стоят фишки-домино с небольшим шагом. Тележка стартует в центре круга. Между фишками она проехать не может, но в одном произвольном месте оставлен проход шириной примерно **20 см**. Задача робота — найти этот проход по изображению с камеры и выехать наружу без контакта с домино.

Метрика успеха простая: робот выехал за пределы круга через целевой проход и не сбил ни одной фишки. В статье приведён результат **8 успешных выездов из 10**.

Проект рассчитан на хобби-инженеров, студентов и разработчиков, которые уже знакомы с Jetson, Arduino, Python и базовым компьютерным зрением. Абсолютному новичку может понадобиться дополнительная подготовка по окружению Jetson.

## Как это работает

Общая цепочка:

```text
CSI-камера
   ↓
Jetson Nano
   ↓
OpenCV + YOLOv5s (TensorRT)
   ↓
Геометрия: точки A, B, E, отрезок EF, длина AB
   ↓
Логика состояний робота
   ↓
Serial → Arduino Nano
   ↓
Драйвер MX1508 → моторы
```

Jetson получает кадр, прогоняет его через оптимизированную модель YOLOv5s в формате TensorRT `.engine`, получает bounding boxes домино. Затем по ним вычисляются ключевые точки и параметры:

- **A** — нижняя средняя точка bounding box левой домино;
- **B** — нижняя средняя точка bounding box правой домино;
- **E** — центр синего прицела, точка пересечения вертикали центра кадра и контрольной горизонтали;
- **EF** — горизонтальное отклонение точки E от линии AB;
- **AB** — расстояние между A и B в пикселях, используется как псевдо-расстояние до выхода.

Когда `AB` превышает порог `AB_END`, робот понимает, что нашёл проход. Дальше он прицеливается, подъезжает и выполняет финальный разворот с выездом.

## Аппаратная часть

Основные компоненты:

- **NVIDIA Jetson Nano 4 GB** — основной вычислитель для CV и логики.
- **Arduino Nano** — низкоуровневый контроллер моторов.
- **CSI-камера IMX219** для Jetson Nano, 160°, 8 MP.
- **Драйвер моторов MX1508**.
- **Два мотор-редуктора TT** (жёлтые) + третье поворотное колесо.
- **Питание**:
  - отдельная батарея 2S 7.4 В для моторов через понижающий преобразователь 5 В / 2 А;
  - отдельная батарея 2S 7.4 В для Jetson через преобразователь 5 В / 4 А;
  - Arduino питается от Jetson по USB.
- **Wi-Fi USB-адаптер** для удалённой отладки.
- **Общая земля** между Jetson, Arduino, драйвером и батареями.

В прототипе использовались стандартные колёса, которые проскальзывали на полу. На них натягивали воздушные шарики — это заметно повысило точность движения. На третье поворотное колесо клеили двусторонний автомобильный скотч, а затем катали по ткани, чтобы оно меньше липло к полу.

Рекомендуется разделять питание вычислительной и силовой части. Моторы дают пусковые токи и помехи, которые могут просаживать напряжение и приводить к зависаниям Jetson.

## Быстрый старт

### 1. Подготовка Jetson Nano

1. Установите JetPack.
2. Проверьте, что работают CUDA, TensorRT и CSI-камера.
3. Установите Python-зависимости:

```bash
pip install opencv-python numpy pyserial
```

4. Убедитесь, что TensorRT и PyCUDA доступны из Python.
5. Положите `best_domino_pol_050524.engine` и `libmyplugins.so` в папку `models/`.
6. Если используете обёртку `YoloTRT`, убедитесь, что путь к `.so` и `.engine` в `app.py` корректный.

Пример инициализации модели:

```python
from yoloDet import YoloTRT

model = YoloTRT(
    library="yolov5/build/libmyplugins.so",
    engine="yolov5/build/best_domino_pol_050524.engine",
    conf=0.6,
    yolo_ver="v5"
)
```

### 2. Подготовка Arduino Nano

1. Откройте `labirint.ino` в Arduino IDE.
2. Проверьте пины:

```cpp
#define MOTOR1_IN 2
#define MOTOR1_PWM 3
#define MOTOR2_IN 4
#define MOTOR2_PWM 5
```

3. Подключите драйвер MX1508 к Arduino и моторам.
4. Подайте питание на драйвер от отдельной батареи.
5. Соедините GND Arduino, Jetson, драйвера и батарей.
6. Загрузите скетч в Arduino Nano.

### 3. Запуск на Jetson

1. Подключите Arduino по USB. Обычно он виден как `/dev/ttyUSB0`.
2. Проверьте порт:

```bash
ls /dev/ttyUSB*
```

3. В `app.py` при необходимости поправьте порт и скорость:

```python
arduino = serial.Serial(
    port='/dev/ttyUSB0',
    baudrate=9600,
    bytesize=serial.EIGHTBITS,
    parity=serial.PARITY_NONE,
    stopbits=serial.STOPBITS_ONE,
    timeout=1
)
```

4. Запустите основной скрипт:

```bash
python3 app.py
```

5. Для отладки удобно подключиться к Jetson по Wi-Fi через `xrdp` и удалённый рабочий стол. IP можно узнать так:

```bash
ifconfig
```

## Как устроена логика робота

Логика разбита на простые фазы. Это делает поведение предсказуемым и упрощает отладку.

### START — стартовое приближение

Робот стоит в центре круга. Нужно подъехать к стене домино и встать примерно под углом 45°, чтобы удобно двигаться вдоль неё.

### Огибание стены

Основная рабочая фаза. Робот движется вдоль стены, ищет пару соседних домино A и B. Если пара найдена, вычисляется длина `AB`. Пока `AB <= AB_END`, робот продолжает огибание и корректирует курс по параметру `EF`.

Идея коррекции: точка E должна скользить по линии AB. Если E отклоняется, робот подруливает правым или левым колесом. Зелёный отрезок EF и число на кадре показывают отклонение в пикселях.

### Прицеливание

Если `AB > AB_END`, значит найден проход. Робот делает мелкие повороты, чтобы вертикаль прицела совпала не с центром прохода, а с точкой на линии AB, отстоящей примерно на **1/3 от точки A**. Поправка `popravka = AB / 3` учитывает габариты робота: так ему удобнее потом развернуться и выехать.

### Приближение

Робот подъезжает к выходу малыми шагами. Если обе домино видны, он совмещает движение вперёд с коррекцией траектории. Когда контрольная линия достигает точки B, выполняется команда `pryamo|` — прямое движение на выверенное расстояние.

Если одна из домино теряется, включается аварийный режим `kluh_1BB`: робот сразу выполняет заранее запрограммированный финальный манёвр, потому что точная коррекция по линии AB уже невозможна.

### FINAL / EXIT

Финальная последовательность: поворот направо на заданный угол и выезд через проход. После успешного выезда — `STOP`.

## Геометрия: как считается EF

На кадре выбирается пара домино: левая и правая относительно вертикального центра. Для них берутся точки A и B.

Вычисляются вспомогательные величины:

```python
b1b = xb - vertikal
eb1 = yb - gorizontal_ef
aa1 = vertikal - xa
a1b1 = yb - ya

if abs(a1b1) < 1e-6:
    ef = 0
else:
    ef = b1b - (eb1 * (aa1 + b1b) / a1b1)
```

Длина AB:

```python
AD = yb - ya
DB = xb - xa
AB = (AD * AD + DB * DB) ** 0.5
```

Смещения для прицеливания:

```python
ac = abs(vertikal - xa)
cb = abs(xb - vertikal)
```

Почему 2D достаточно? Камера жёстко закреплена под фиксированным углом и высотой. Домино стоят на плоском полу. При таких условиях вертикальная координата в кадре связана с расстоянием, а горизонтальная — с боковым смещением. Полное 3D-восстановление не требуется: система работает на относительных величинах в пикселях. Все пороги подобраны эмпирически под конкретную камеру, разрешение и крепление.

## Ключевые параметры

| Параметр | Что делает | Стартовое значение | Как настраивать |
|---|---|---|---|
| `FRAME_SKIP` | Обрабатывать каждый N-й кадр | 15 | Уменьшить для отзывчивости, увеличить для стабильности |
| `vertikal` | X-центр кадра | 360 px при ширине 720 | Подстроить под разметку |
| `gorizontal_ef` | Y контрольной горизонтали | 230 px | Меняет фактическое расстояние до стены при огибании |
| `AB_END` | Порог AB для перехода к прицеливанию | 300 px | Измерить AB выхода в пикселях |
| `distanziy_start` | Порог завершения стартового приближения | 250 px | Чтобы робот встал удобно для огибания |
| `d_ac_cb` | Допуск при прицеливании | 30 px | Больше — мягче, меньше — жёстче |
| `popravka` | Поправка прицеливания | `AB / 3` | Пробовать `AB/4..AB/2` |
| `conf` | Порог уверенности YOLO | 0.6 | Ниже — больше ложных, выше — больше пропусков |

## Команды Serial

Jetson отправляет Arduino команды в формате:

```text
<command>[_<value>]|
```

Примеры:

- `pryamo|` — прямо;
- `levee_700|` — влево;
- `pravo1|` — малый поворот вправо;
- `levo1|` — малый поворот влево;
- `pribligenie|` — приближение;
- `levostart|` — стартовый манёвр;
- `pravoitog_20|` — финальный разворот вправо на угол.

Arduino читает строку до `|`, отделяет имя команды до `_` и опциональное значение после `_`.

Пример на стороне Jetson:

```python
comand = "pravoitog_" + str(ugol) + "|"
arduino.write(comand.encode())
```

На стороне Arduino:

```cpp
String receivedCommand = Serial.readStringUntil('|');
int delimiterIndex = receivedCommand.indexOf('_');

String commandName;
int value_v = 0;

if (delimiterIndex >= 0) {
    commandName = receivedCommand.substring(0, delimiterIndex);
    value_v = receivedCommand.substring(delimiterIndex + 1).toInt();
} else {
    commandName = receivedCommand;
}
```

## Arduino: управление моторами

Arduino не принимает решений. Он выполняет короткие заранее прописанные манёвры по командам от Jetson.

Функция `motorControl()` преобразует логическую скорость в направление и ШИМ:

```cpp
void motorControl(int val, byte pinIN, byte pinPWM) {
    val = constrain(val, -1023, 1023);
    int pwm = map(abs(val), 0, 1023, 0, 255);

    if (val > 0) {
        digitalWrite(pinIN, LOW);
        analogWrite(pinPWM, pwm);
    } else if (val < 0) {
        digitalWrite(pinIN, HIGH);
        analogWrite(pinPWM, pwm);
    } else {
        digitalWrite(pinIN, LOW);
        analogWrite(pinPWM, 0);
    }
}
```

Остановка:

```cpp
void stopMotors() {
    motorControl(0, MOTOR1_IN, MOTOR1_PWM);
    motorControl(0, MOTOR2_IN, MOTOR2_PWM);
}
```

В прототипе используется блокирующая логика с `delay()`. Это просто и предсказуемо, но на время задержки Arduino не может делать ничего другого. Для развития проекта лучше перейти на неблокирующее управление через `millis()`.

## Экспорт в TensorRT

Для Jetson модель переводилась в TensorRT `.engine`. Использовался публичный репозиторий **JetsonYolov5**: https://github.com/ultralytics/yolov5

Схема:

```text
YOLOv5 .pt → .wts → TensorRT .engine
```

В коде используется обёртка `YoloTRT`:

```python
from yoloDet import YoloTRT

model = YoloTRT(
    library="yolov5/build/libmyplugins.so",
    engine="yolov5/build/best_domino_pol_050524.engine",
    conf=0.6,
    yolo_ver="v5"
)

detections, t = model.Inference(frame)
```

Обёртка сама делает letterbox, запускает TensorRT, выполняет постобработку и возвращает координаты боксов в пикселях исходного кадра.

## Результаты и известные проблемы

Из 10 запусков — **8 успешных выездов** без контакта с домино.

Известные баги:

1. **Выезд не в проход.** Робот не заметил одно домино между двумя другими и посчитал `AB` не между соседними фишками, а через одну. `AB` сразу стало большим, и запустилась фаза выезда. Решение — мультикадровая проверка: считать детекцию истинной, если она подтверждается в N из K последних кадров.

2. **Сдвиг домино на выезде.** Вместо поворота на 90° робот повернулся примерно на 120°. Причина — нестабильность третьего опорного поворотного колеса. Решение — сделать третью опору более предсказуемой.

Дополнительные ограничения:

- детекция зависит от освещения: при слабом свете много пропусков;
- возможны ложные срабатывания на предметах фона;
- порог `conf` нужно подбирать под сцену;
- 10 запусков — предварительная статистика, для выводов лучше 30–50.
